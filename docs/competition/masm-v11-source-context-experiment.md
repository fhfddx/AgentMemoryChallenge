## 最小实现

- `MASM_SOURCE_CONTEXT_ENABLED=1` 才启用；默认关闭，关闭时保留 d74ad1c 行为。
- 排序之后、selector 之前，按同用户、同 Add request、精确位置读取命中消息及
  前后各一条。这个窗口用于恢复对话局部语境，不用于推断关系图的跳数。
- 原文、role、position 和原有 timestamp 使用 JSON 表达。角色仅表示消息发送方，
  不自动把第三人称人物当作用户，不把建议或问句变成事实。
- 保持候选索引、记忆 ID、排名、分数和来源分组；selector prompt、阈值不改。
- 总字符上限沿用 selector 配置（默认 1200）。加入完整消息才算成功；超过预算
  的邻居只记录 omitted_positions，不截取可能掩盖否定的半句。锚点本身不适用
  或过长则维持原路径。多模态锚点维持原路径。
- selector 看到的上下文与最终 renderer 返回的上下文一致，避免筛选依据丢失。
- 不改数据库 schema，无额外模型调用。不跨用户、跨 Add 自动拼接对话。

## 验证顺序和预先固定的门槛

1. 单元与真实本机数据库/API 测试：角色/时间保留，用户隔离，否定回答上下文，
   多模态兼容，预算和 JSON 转义，100 个候选分批读取，开关关闭行为。
2. `scripts/source_context_probe.py`：10 个固定案例、每例 baseline/context 两次
   selector 调用，使用相同 prompt、模型和召回候选；唯一变量为来源上下文。
   这个脚本只使用内存合成资料，不访问数据库，不写入服务器数据。
3. 第一轮出现任何候选失败即停止，按失败原因处理，不通过追加重复次数挑选好结果。
   首轮全部通过后才进行反向调用顺序和再一轮，共最多 60 次模型调用。
   每轮要求 candidate_passed=10、regressions=0、candidate 严格优于 baseline。
   脚本成功只证明证据选择覆盖，不证明答案正确或官方分数。
4. 上述门槛通过后仍须跑实际 Add→Search 回归和语义断开链负例，再考虑 API-only
   候选部署及用户授权的官方 Smoke。Full 不运行。

固定案例包括省略回答、后续纠正、只有问题、未采纳的助手建议、已采纳建议、
跨来源指代、错误主体、自包含直接事实、双来源事实、中文对话。

## 先保留本次 Smoke 的脱敏证据

`scripts/search_window_summary.py` 从 stdin 接收 Docker 日志，只输出固定枚举与
计数，不输出原始行、用户标识、问题、来源正文或错误文本。失败日志只计为非 JSON
或无关事件。输入窗口由用户截图的北京时间完成时间 18:37:57、耗时 5m16s 确定，
建议 UTC 10:32:00 到 10:39:00（带余量，不能保证没有其他请求）。

在重建旧 API 容器前运行摘要；否则其日志可能不再可用。摘要没有 search_rows 时
返回非零，不把缺少日志当作零失败。不得把并发请求的完成顺序对应为固定隐藏题号。
