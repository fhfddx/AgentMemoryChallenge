# 空历史文本写入延迟试验设计

## 目标与边界

目标是降低 v1.1 纯文本、无同用户历史时的 Add 延迟，同时保留时间字段、原始证据和降级语义。已有本机计量显示感知与时序为两次串行 LLM 调用；HTTP Client 复用不是该计量环境中约 3.5 秒 Add 延迟的解释。本试验不更改官方 Add/Search 契约，不触及图片、有历史记忆、线上环境、官方评测和容量测试。

## 设计

新增一个仅处理有序文本分片的融合智能体，一次结构化模型调用返回 `PerceptionResult` 和写入实际使用的 `event_time` / `time_precision`，有时间时另带必须逐字出现在输入中的 `time_evidence`。提示词同时遵守现有感知与时间的证据约束；无历史时不生成无用的关系、事件排序或时间表达数组。流水线将时间字段转换为既有 `TemporalRelationResult`。现有两阶段路径保留。

运行时以显式配置开关启用试验，默认关闭。流水线仅在纯文本且预检无同用户 `context` 历史（或 `max_history=0`）时尝试融合。融合之后仍执行既有召回；若并发写入使历史候选出现，时序重新走原有分析，治理不被跳过。融合结构化输出或忠实性校验失败时回退到原两阶段路径；传输失败遵守现有降级行为。开关关闭时行为不变。

新增不含正文与密钥的计量：融合调用类型、融合阶段耗时。离线测试覆盖纯文本空历史、显式日期、禁用开关、图片、有历史、无效融合输出回退和并发历史变化。受限正式 Provider 小样本只在离线全量通过后运行；比较同一固定输入的旧/新 v1.1 Add 延迟、时间字段及调用量。首轮完整嵌套时序输出已观测 1/3 融合回退、输入/输出 token 增加、P95 上升，故收窄输出后才进行第二次限定验证。若融合质量或成本不达标，保持默认关闭，不宣称实测提速。

## 决策与风险

相比直接跳过时序模型，融合保留时间提取能力；相比对所有路径融合，它限制了影响面。预检额外增加一次本机数据库查询，可能抵消少量收益；模型输出更复杂，也可能导致重试或质量下降。只有实测覆盖、时间字段与失败率均可接受时才考虑默认启用。用户此前明确要求继续推进且无需就常规路线反复询问；因此本阶段在已有工作树内执行，不提交或推送现有未提交改动。
